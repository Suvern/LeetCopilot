# Contributing

1. Create a focused branch from the default branch.
2. Keep changes scoped and avoid including API keys, personal LeetCode data, or generated `dist` output.
3. Run `npm run typecheck`, `npm test`, `npm run lint`, and `npm run build` before opening a pull request.
4. Describe browser and `leetcode.cn` versions when reporting page-integration issues.

Pull requests should include tests for shared logic and a clear manual verification note for UI changes.
